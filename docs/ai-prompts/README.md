# AI 협업 기록 작성 규칙

AI를 활용한 작업의 요구사항과 의사결정 과정을 추적하기 위해 PR마다 협업 기록을 작성한다.

## 기본 규칙

- AI를 활용한 PR에는 협업 기록을 정확히 한 개 포함한다.
- 기록은 해당 기능 PR에 함께 커밋한다.
- PR을 생성해 번호가 정해진 후, 머지 전에 기록 파일을 추가한다.
- 전체 대화 원문보다 핵심 요청과 의사결정을 중심으로 요약한다.
- 사용자가 결정한 내용과 AI가 수행한 작업을 구분한다.
- 기획 문서의 `(안)`, `TODO`, `⚠ 차이` 항목을 결정했거나 바꾼 경우 주요 결정에 기록한다.
- 비밀번호, 토큰, 개인 정보, 불필요한 로컬 경로 등 민감한 정보는 기록하지 않는다.
- 단순한 도구 호출이나 반복적인 확인 과정은 결과에 영향을 준 경우에만 기록한다.
- 머지된 기록은 사실관계 수정이 필요한 경우를 제외하고 변경하지 않는다.

이 규칙을 처음 도입하는 PR(공통 문서 `CLAUDE.md`, `GIT_WORKFLOW.md`, `docs/PROJECT_PROGRESS.md`, 이 문서를 추가하는 PR)은 부트스트랩 예외로 협업 기록을 요구하지 않는다.

## 파일 이름

```text
docs/ai-prompts/pr-{PR번호}-{기능명}.md
```

예시:

```text
docs/ai-prompts/pr-003-quench-liquid-select.md
```

- PR 번호는 세 자리로 맞춘다.
- 기능명은 짧은 영문 kebab-case를 사용한다.

## 작성 템플릿

```markdown
# PR #{번호}: {PR 제목}

## 개요

- 브랜치: `{브랜치 이름}`
- 대상 브랜치: `dev`
- PR: #{번호}
- 작성일: YYYY-MM-DD
- 담당 영역: {게임플레이·제작 / 시스템·데이터 / 네트워크·플랫폼}
- 작업 목적: {작업 목적}

## 주요 요청

1. {사용자의 핵심 요청}
2. {추가 요청 또는 제약사항}

## AI와 논의한 내용

### {논의 주제}

{검토한 선택지와 논의 결과}

## 주요 결정

- {사용자가 확정한 결정}
- {구현 과정에서 확정된 결정}

## 변경된 주요 파일

- `{파일 경로}`

## 검증 내용

- {수행한 검증과 결과}

## AI 활용 범위

{AI가 지원한 작업과 사용자가 직접 결정하거나 확인한 내용을 구분해 작성}

## 후속 작업

- {이번 PR 범위에 포함하지 않은 작업}
```
