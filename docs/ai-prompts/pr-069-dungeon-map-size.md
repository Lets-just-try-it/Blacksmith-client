- 작업 목적: 등장하는 몬스터 수에 비해 던전 맵이 너무 크다는 피드백을 반영해, 낮은 단계는 작은 맵, 높은 단계는 큰 맵과 많은 무리를 두도록 조정한다.

## 주요 요청

1. 던전별 총 몬스터 수와 무리 수를 제안하고, 단계에 따라 맵 크기와 무리 수를 함께 늘리는 계획을 세운다.
2. 2단계는 무리를 늘리는 쪽(선택 A)으로 적용한다.
3. 제안한 3~5단계 수치도 기획 문서에 넣는다.

## AI와 논의한 내용

### 맵 크기와 무리 밀도

모든 단계가 같은 맵 수치를 써서 무리당 바닥 넓이가 5,000~10,000m²였다. 무리 하나(보스 포함)당 2,000~4,000m²를 기준으로 삼고, 맵 수치는 스테이지마다가 아니라 지금처럼 던전마다 하나로 두기로 했다. 그러면 코드를 바꾸지 않아도 된다.

### 2단계 무리 수

선택지는 두 가지였다. A는 무리를 늘리고 골드도 약 20% 늘린다. B는 몬스터 수를 그대로 두고 맵만 줄인다. 사용자가 A를 골랐다.

### 측정에 따른 수치 조정

제안 수치를 시드 200개로 측정해 고쳤다.
- 1단계는 처음 제안(100~130m)으로는 가장 작은 맵이 너무 작고 스폰 거리 조건을 줄이는 경우가 8% 있어서, 110~140m, 덩어리 4~5개로 키웠다.
- 3~5단계는 처음 제안으로는 4·5단계 무리당 넓이가 기준을 넘고, 3단계가 4단계와 크기가 거의 같아서 모두 조금 줄였다.

## 주요 결정

- 사용자: 2단계 무리 수 확대(선택 A), 3~5단계 수치를 문서에 반영.
- 구현 중 확정:
  - 무리당 바닥 넓이 2,000~4,000m², 무리 하나 최대 5마리.
  - 1단계 무리 구성은 유지한다(1스테이지 1명 클리어 기준).
  - 3~5단계는 문서에만 [추정]으로 두고, 데이터는 만들지 않는다.

## 검증 내용

- `Core/Battle` 맵 생성 규칙을 Unity 밖에서 시드 200개로 돌려, 단계별 맵 넓이, 무리당 넓이, 스폰 거리 조건을 줄인 비율, 이동 시간을 측정했다.
- 모든 시드에서 무리가 다 놓였다.
- 사용자가 플레이 모드로 1단계 1스테이지 1명 클리어와 2단계 난이도를 확인했다. 1단계 채집 맵의 자원 밀도도 괜찮다고 확인했지만, 추후 테스트로 조정할 수 있다.

## AI 활용 범위

AI가 한 일:
- 현재 데이터와 맵 생성 코드를 분석했다.
- 수치를 제안하고, 시드로 측정해 조정했다.
- 데이터 에셋과 기획·진행 문서를 고쳤다.

사용자가 한 일:
- 2단계 무리 확대안을 고르고, 3~5단계 반영을 결정했다.
- 플레이 모드로 확인했다.
- 커밋과 PR을 승인했다.
