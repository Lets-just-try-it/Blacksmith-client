- 대상 브랜치: `dev`
- PR: #27

- 담당 영역: 시스템·데이터
- 작업 목적: 전체 던전 단계 수를 정하고 3~10단계 몬스터 구성을 기획 문서에 반영

## 주요 요청

1. 현재 몬스터 데이터 구조 확인
2. 전투에서 타겟팅을 하는지, 충돌로 피해를 주는지 확인
3. 최종 보스까지 10단계로 가정한 몬스터 구성 제안
4. 제안한 구성을 기획에 반영

## AI와 논의한 내용

### 현재 몬스터 데이터와 전투 방식

`MonsterData`(능력치, 스킬 순환, 분노, 외형 프리팹)와 `DungeonData`(스테이지별 스폰과 보상)의 구조, 1~2단계 몬스터 8종의 수치를 정리했다. 전투는 충돌 처리 없이 `BattleSimulation`이 1차원 위치에서 매 틱 가장 가까운 적을 다시 골라 사거리 안이면 공격하고, 사거리 밖이면 다가가는 방식임을 확인했다.

### 10단계 몬스터 구성

지금 전투 규칙만으로 만들 수 있도록 단계마다 잡몹을 근접·원거리·특수 세 역할로 나누고, 단계별로 새 요소(아군 전체 회복, 순간 화력, 높은 방어 등)를 하나씩 더하는 안을 제안했다. 보스 체력은 2.2배 증가를 유지하면 10단계에서 지나치게 커지므로 3단계부터 1.5~1.7배를 기준으로 제안했다. 후열 노리기, 소환, 여러 번의 분노 같은 아이디어는 지금 규칙에 없으므로 고도화로 분리했다.

### 반영 범위

기획 문서만 반영할지, 데이터 에셋까지 만들지 검토했다. 외형 프리팹이 없고 수치가 추정 단계라서 문서만 반영하기로 했다.

## 주요 결정

- 사용자 결정: 전체 던전은 10단계, 10단계 보스는 마왕 (결정 표 9번 [미정] → 확정)
- 사용자 결정: 이번 PR은 기획 문서만 반영하고, 데이터 에셋은 만들지 않는다
- 사용자 결정: 기존 작업 브랜치와 분리해 `dev`에서 새 브랜치로 작업한다
- 3~10단계 몬스터 구성, 보스 스킬 순서, 분노 비율, 보스 체력 증가 기준은 [추정]으로 둔다
- 3~10단계 보스 재료와 제작 난이도의 대응은 [미정]으로 남기고 대장간 담당과 정한다
