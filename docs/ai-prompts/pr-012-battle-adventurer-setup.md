## 주요 요청

1. 전투 작업 다음으로 할 일을 정리할 것. 작업 도중 광장 PR이 병합되어 다시 확인할 것
2. 모험가 데이터 → 전투 유닛 변환부터 진행할 것
3. 생성된 전투 유닛에서 모험가 데이터를 확인할 수 있게 할 것

## AI와 논의한 내용

### 다음 작업 순서

AI가 진행 현황 문서, 병합된 PR, 기획 문서의 [미정]·[담당자 결정] 항목을 확인해 전투 쪽 남은 작업을 정리했다. 처음에는 결과 처리 규칙(보상·경험치)을 먼저 제안했다. 광장 PR(#10)이 병합된 뒤 다시 확인하고, 모험가 데이터를 전투 입력으로 바꾸는 작업이 다른 작업(Fusion 연동, 결과 반영)의 전제라서 순서를 바꿔 제안했다. 사용자가 변환부터 하기로 했다.

### 직업별 전투 수치를 둘 위치

광장의 `AdventurerJobData`에는 직업별 공격 방식을 전투 담당이 추가한다는 주석이 있다. AI는 다른 영역 파일을 고치지 않도록 전투 쪽에 `AdventurerBattleData`를 따로 두고 직업 번호로 찾게 했다. 스킬 번호 → `SkillData` 표도 같은 에셋에 두었다.

### 아직 정하지 않은 보정

장비·직업 보정과 직업별 공격 방식은 기획상 [미정]이라 넣지 않았다. 체력·공격력·방어력은 관리 목록 화면과 같은 `AdventurerStatRules.GetCurrentStats`를 써서, 화면과 전투가 같은 값을 쓰게 했다.

### 유닛에서 모험가 정보 확인

사용자가 씬에 생성된 유닛에서 모험가 데이터를 볼 수 없는지 물었다. AI가 유닛 뷰에는 인스펙터에 나오지 않는 전투 상태만 있고, 원본은 테스트 시작점의 비공개 목록에만 있다고 설명했다. 이름만 바꾸는 방법과 표시용 컴포넌트를 붙이는 방법을 제안했고, 사용자가 이름과 정보 컴포넌트를 함께 넣는 방법을 골랐다.

## 주요 결정

- 모험가 데이터 → 전투 유닛 변환을 먼저 한다. (사용자 결정)
- 직업별 전투 수치와 스킬 표는 전투 쪽 `AdventurerBattleData`에 두고, 광장 파일은 수정하지 않는다. (AI 제안, 사용자 승인)
- 장비·직업 보정은 넣지 않고 [미정]으로 둔다. (기획 문서 기준)
- 전사 전투 수치와 스킬 1번은 기존 테스트 모험가 수치를 옮긴 임시값이다. (AI 제안, 사용자 승인)
- 테스트 씬은 광장과 같은 생성 규칙과 시드로 파티를 만들고, 레벨은 인스펙터에서 지정한다. (AI 제안, 사용자 승인)
- 생성된 유닛에 표시용 `AdventurerUnitInfo`를 붙이고 오브젝트 이름을 `이름 Lv레벨 (#ID)`로 바꾼다. (사용자 결정)
- 에디터가 자동으로 바꾼 무관한 파일(폰트 아틀라스, Fusion 설정, 줄바꿈만 바뀐 ProjectSettings)은 커밋하지 않는다. (사용자 승인)
