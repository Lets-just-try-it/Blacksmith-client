- 작업 목적: 재료·제작 밸런스 기획서를 기획 문서와 아이템 데이터에 반영함

## 주요 요청

1. 새 브랜치를 만들고, 재료·제작 밸런스 기획서의 재료와 아이템을 기획에 반영할 것
2. 기획서의 "던전 3단계까지가 목표"는 최종 목표를 말한다. 최종 목표는 던전 5단계로 바꿀 예정이니 다시 적고, MVP는 2단계까지로 둘 것
3. 던전 5단계 구성은 1 해골, 2 오크·고블린, 3 얼어붙은 산맥, 4 화염 화산, 5 마왕성으로 할 것
4. 철을 티어 2로 옮기고 구리를 새로 추가할 것
5. 기획 문서뿐 아니라 아이템 데이터까지 반영하되, 코드 변경 없이 데이터로만 할 것

## AI와 논의한 내용

### 반영 범위

AI가 기획 문서와 아이템·레시피·던전 데이터 구조를 확인하고 사용자에게 범위를 물었다. 레시피는 단계마다 물건 하나를 받고 재료 개수를 받지 않는다. 던전 보상도 고정 개수만 받는다. 그래서 "광석 4 + 가죽 2" 같은 재료 수와 부재료·보석의 확률 드랍은 코드 변경이 필요했다. 사용자는 데이터만 반영하기로 했고, 나머지는 담당자 확인 뒤 별도 작업으로 남겼다.

### 던전 구성

기획서의 "3단계 목표"와 기획 문서의 "MVP 2단계"가 달라 보여 AI가 확인을 요청했다. 사용자는 3단계가 최종 목표를 뜻한다고 설명했고, 최종 목표를 5단계로 바꾸고 MVP는 2단계로 두기로 했다. 5단계 구성도 사용자가 정했다. AI는 1단계 "해골"을 기존 버려진 묘지의 몬스터로 적었다. 2단계 오크·고블린의 몬스터 구성과 보스는 정해지지 않아 [미정]으로 두었다. 지금 던전 데이터와 지도 창은 이전 구성이라, 바꾸는 작업을 전투 담당의 남은 작업으로 적었다.

### 티어 1 재료

기획서는 티어 1을 구리, 티어 2를 철로 둔다. 기존 데이터는 철 계열이 티어 1이었다. 사용자는 철을 티어 2로 옮기고 구리를 새로 추가하기로 했다. 작업대는 레시피를 하나만 받는다. 그래서 AI는 작업대가 쓰는 `WeaponRecipe`를 구리 대검 단계로 바꾸고, 철 대검 단계는 `IronWeaponRecipe`로 따로 두는 방법을 택했다. 이렇게 하면 `ForgeRoom` 프리팹을 고치지 않아도 되고, 철 장비가 업그레이드 2단계에서 열린다는 기획과도 맞는다.

## 주요 결정

- 재료 10종, 장비별 재료 수, 장신구 효과, 업그레이드 6단계, 던전 드랍, 사망·부상 규칙을 기획 문서에 반영한다. 수치는 [추정]으로 둔다.
- 장신구 해금 레벨은 업그레이드 3단계로 정하고, 업그레이드 비용은 [추정] 값으로 채운다.
- 사망하면 입힌 장비도 사라진다.
- 전체 던전은 5단계(1 버려진 묘지(해골), 2 오크·고블린, 3 얼어붙은 산맥, 4 화염 화산, 5 마왕성)이고 MVP는 2단계다.
- 철 계열은 티어 2, 구리 계열은 티어 1로 새로 추가한다. 기존 아이템 번호는 바꾸지 않는다.
- 레시피 재료 개수, 확률 드랍, 장신구 효과, 미스릴 장비, 업그레이드 구현은 이번 PR에 넣지 않는다.

## AI 활용 범위

AI가 밸런스 기획서와 기존 기획 문서·데이터를 비교했다. 충돌하거나 정해지지 않은 부분은 사용자에게 물었다. 그 뒤 기획 문서 수정, Unity CLI로 아이템·레시피·던전 데이터와 씬 시작 재료 변경, 테스트와 플레이 모드 확인, 진행 문서 수정을 했다. 사용자는 기획서를 제공했고, 최종 던전 단계 수와 구성, 티어 1 재료 처리, 데이터만 반영하는 범위를 정했다. 커밋과 PR 내용도 확인해 승인했다.
