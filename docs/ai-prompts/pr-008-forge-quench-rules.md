# PR #8: feat: 미니게임 기반과 담금질 규칙 추가

## 개요

- 브랜치: `feat/forge-quench-rules`
- 대상 브랜치: `dev`
- PR: #8
- 작성일: 2026-11-01
- 담당 영역: 게임플레이·제작 (`Forge/`, `Core/Forge/`)
- 작업 목적: 별도 프로토타입의 제작 미니게임을 현재 구조로 옮기는 첫 단계로, 미니게임 기반과 담금질 규칙을 `Core`에 만들고 수치를 데이터로 분리한다.

## 주요 요청

1. 프로토타입 미니게임 7종 중 첫 번째로 담금질을 옮기고, 이식은 PR을 나눠 진행할 것
2. 작업 중 필요한 기획 내용은 하나씩 사용자에게 물어서 정할 것
3. 담금질 방식이 5단계 등급 계산에 맞는지 확인할 것
4. 대장간 영역 작업의 브랜치 이름에는 `forge`를 붙일 것

## AI와 논의한 내용

### 이식 범위와 구조

AI가 기반(`MiniGame`, `MiniInput`, `MiniEvent`)만 먼저 옮기면 쓰는 곳이 없어 테스트할 수 없다고 설명하고, 가장 작은 담금질을 함께 옮기자고 제안했다. 팀원의 전투 구조(`Core/Battle`의 규칙 클래스와 `Battle/`의 ScriptableObject)와 같은 방식으로 `Core/Forge`의 규칙 클래스와 `Forge/`의 ScriptableObject로 나누기로 했다.

### 기획을 하나씩 확인

AI가 구현 전에 필요한 기획 내용을 하나씩 질문하고 사용자가 답했다.
- 담금질 `Trait`(장비에 남기는 성질): 이번에는 뺀다. 부가 옵션은 아직 [담당자 결정]이다.
- 담금질 규칙: 프로토타입 규칙을 그대로 기획에 반영한다.
- 수치: 프로토타입 값을 그대로 옮기고 [추정]으로 표시한다.
- 난이도 출처: 상위 던전 단계에서 얻는 새 재료로 만든 장비가 더 어렵다. 난이도 단계는 0, 1, 2 세 단계 수치를 모두 데이터로 둔다.
- 미니게임 도중 취소: 없다. 프로토타입의 Esc 취소는 옮기지 않는다.
- 공통 규칙: 준비·선택 구간 자동 진행과 제한시간을 기획에 반영한다.

### 등급 계산과의 적합성

사용자가 담금질 구조가 5단계 등급의 점수 반영에 적절한지 확인해 달라고 했다. AI가 프로토타입 공식과 난이도 자료로 계산했다.
- 구조는 맞다. 정확도가 `0~1` 연속값이고 실패가 없으며 수치가 데이터다.
- 어려움(난이도 2)은 기준 시간이 길어지면서 허용 오차도 좁아져서 5등급을 받으려면 대략 ±0.26초 안에 꺼내야 한다.
- 담금질은 단계별 점수의 폭이 커서 평균 등급에 미치는 영향이 크다.

사용자는 수치를 그대로 옮기고 플레이 테스트 후 조정하기로 했다.

### 프로토타입의 초 알림 문제

AI가 작성한 테스트가 프로토타입의 2초 알림이 경과 시간 2.000~2.001초 사이일 때만 나오는 문제를 잡았다. 프레임 간격이 그보다 길어 알림이 거의 빠졌을 것이므로, 의도대로 고쳤다.

### 화면·입력 시점과 브랜치

- 화면과 입력은 다음 PR에서 붙이기로 했다. AI가 처음에는 모든 규칙을 옮긴 뒤 붙이는 순서를 제안했으나, 직접 해 보는 시점이 너무 늦어진다는 점을 짚고 다음 PR에서 붙이는 쪽으로 정했다.
- 원격 `feat/forge` 브랜치는 사용자가 작업하도록 만들어 둔 빈 브랜치였다. 기능별 새 브랜치를 쓰기로 했다.
- 사용자가 대장간 작업 브랜치에는 `forge`를 붙이자고 제안해 `feat/minigame-quench`를 `feat/forge-quench-rules`로 바꿨다. `feat/forge`와 슬래시로 겹치지 않도록 하이픈으로 이었다.

### PR 단위

사용자가 규칙, 입력, 화면을 따로 올리면 PR이 너무 많아진다고 지적했다. AI가 미니게임별 한 PR, 제작 종류별 묶음, 규칙과 화면 분리 세 방식을 비교했다. 사용자는 제작 종류별 묶음을 골랐다가, 병합을 직접 하고 PR이 많아도 문제가 없다는 이유로 원래대로 작은 PR을 하나씩 올리는 방식으로 되돌렸다. 브랜치 이름을 바꾸면 열린 PR이 닫히는 GitHub 동작을 확인했고, 이 PR은 그대로 유지한다.

## 주요 결정

- 담금질은 `Trait` 없이 정확도(`0~1`)만 낸다. (사용자 결정)
- 담금질 규칙과 수치는 프로토타입 그대로이고, 수치는 [추정]이다. (사용자 결정)
- 제작 난이도는 재료 단계가 정하고, 난이도 0, 1, 2 수치를 데이터로 둔다. 재료와 난이도의 대응은 [미정]이다. (사용자 결정)
- 미니게임 도중 취소는 없고, 자동 진행과 제한시간은 공통 규칙이다. (사용자 결정)
- 입력과 화면은 다음 PR로 미룬다. (사용자 결정)
- 이식은 규칙, 입력·화면, 네트워크 연결을 작은 PR로 하나씩 올린다. (사용자 결정)
- 이벤트 종류를 5개로 줄이고 `Success`/`Fail`은 없앤다. 실패가 없는 규칙과 맞지 않아서다. (AI 제안, 사용자 승인)
- 브랜치 이름은 `feat/forge-quench-rules`. (사용자 제안)

## AI 활용 범위

AI가 프로토타입 분석, 구조 설계 제안, 코드·테스트·문서 작성, 수치 분석, Unity CLI를 통한 에셋 생성과 테스트 실행을 맡았다. 사용자는 기획 항목(성질, 규칙, 수치 표시, 난이도 출처, 취소, 공통 규칙), 입력·화면 시점, PR 단위, 브랜치 이름을 직접 결정했다. 커밋과 PR 내용은 AI가 초안을 보이고 사용자가 승인했다. 기획 변경의 팀 공유는 사용자가 직접 한다.
