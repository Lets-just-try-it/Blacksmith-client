# PR #15: feat: 담금질 작업대 상호작용과 카메라 포커스, 화면 추가

## 개요

- 브랜치: `feat/forge-quench-input`
- 대상 브랜치: `dev`
- PR: #15
- 작성일: 2026-11-03
- 담당 영역: 게임플레이·제작
- 작업 목적: 대장간 맵의 담금질 작업대에서 상호작용 키로 담금질 미니게임을 시작하고, 카메라 포커스와 결과 화면까지 로컬로 진행해 볼 수 있게 한다.

## 주요 요청

1. 담금질 기능을 작업한다. 별도 테스트 화면이 아니라 대장간 맵의 작업대에서 카메라를 옮겨 진행한다.
2. 준비 구간의 자동 시작을 없앤다.
3. 정확도를 간단한 UI로 보여 준다. 이후 프로토타입에서 만들었던 시간선 방식으로 바꾼다.
4. 담금질 범위를 지정하고, 범위를 벗어나면 담금질이 되지 않게 한다. 바닥 표시는 필요 없고 텍스트 안내로 충분하다.
5. 한 번 범위에 들어가면 이후 벗어나도 계속 담금질이 되는 문제를 고친다.
6. 담그는 키를 누른 순간부터 딜레이 없이 시간을 세도록 바꾼다.

## AI와 논의한 내용

### 작업 범위와 브랜치

PR을 작게 나누는 방침에 따라 이번 PR은 로컬 담금질 화면까지로 정했다. 작업대 사용권과 결과의 호스트 전송은 다음 PR로 미뤘다. `ForgeRoom`이 PR #14로 이미 병합되어 있어 `dev`에서 새 브랜치를 만들었다.

### 이동 잠금과 Network 공개 API

담금질 중 캐릭터가 움직이지 않게 하려면 `Network/`의 `PlayerInputCollector`에 속성을 추가해야 했다. 입력 액션을 직접 끄는 방법과 비교한 뒤, 숨은 결합이 생기지 않도록 `MovementLocked` 속성 하나를 추가하는 방식으로 정했다.

### 카메라 포커스

시험용 카메라 추적(`ForgeTestCameraFollow`)과 겹치지 않도록 별도 컴포넌트(`ForgeCameraFocus`)가 포커스와 복귀를 맡고, 포커스 중에는 추적이 물러나게 했다. 처음 잡은 카메라 위치에서는 내 캐릭터가 수조를 가려서 카메라 마커와 칼날 위치를 옮겼다.

### 범위 판정

트리거 이벤트(`OnTriggerEnter/Exit`)만으로는 범위를 벗어난 뒤에도 상호작용이 남는 문제가 있었다. 대장간 문(`ForgeDoor`)과 같은 방식으로, 매 프레임 위치가 범위 안인지 직접 확인하도록 바꿨다.

### 결과 화면

처음에는 정확도 막대 게이지로 만들었으나, 폐기한 프로토타입 브랜치의 결과 화면을 참고해 시간선(기준 시간 표시, 완벽 구간, 꺼낸 시간 마커)과 한 줄 설명으로 바꿨다. 이를 위해 `QuenchGame`에 완벽 구간(`PerfectBand`)을 노출했다.

## 주요 결정

- 사용자가 확정한 결정
  - 준비 구간 자동 시작을 제거한다. (기획 변경)
  - `PlayerInputCollector.MovementLocked` 추가를 승인한다.
  - 담금질 범위는 바닥 표시 없이 텍스트 안내로 충분하다.
  - 결과 정확도는 프로토타입 방식의 시간선으로 보여 준다.
  - 담그는 키를 누른 순간부터 시간을 센다. (기획 변경)
- 구현 과정에서 확정된 결정
  - 담금질은 이 클라이언트에서만 로컬로 진행하고 끝난 정확도는 `Completed` 이벤트로 알린다.
  - 칼날이 수조로 옮겨지는 연출 시간은 화면에만 쓰고 시간 계산에는 쓰지 않는다.
  - 칼날 색은 꺼내기 전까지 바꾸지 않는다. 식는 모습이 기준 시간의 힌트가 되지 않게 하기 위해서다.
- 기획 변경: `docs/GAME_CONCEPT.md` 담금질 항목에서 준비 구간 자동 시작 제거, 담그는 순간부터 시간 계산으로 고쳤다. 팀 공유가 필요하다.

## 검증 내용

- EditMode 테스트 70개가 통과했다.
- ForgeTest 씬 플레이 모드에서 범위 안에서 시작, 담그기, 꺼내기, 종료 후 카메라 복귀를 확인했다.
- 범위 안에 들어갔다가 벗어난 뒤에는 키를 눌러도 시작되지 않고, 다시 들어오면 시작되는 것을 확인했다. 범위 밖 이동은 순간이동으로 확인했고 직접 걸어서는 확인하지 못했다.
- 샘플 결과 값으로 결과 화면(정확도, 시간선, 설명)을 화면에 띄워 모양을 확인했다. 실제로 한 판을 끝까지 진행한 화면은 보지 못했다.
- 시간을 담그는 순간부터 세는 변경은 테스트로만 확인했고 플레이 모드에서는 다시 확인하지 못했다.
