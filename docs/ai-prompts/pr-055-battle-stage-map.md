## 개요

- 브랜치: `feat/battle-stage-map`
- 대상 브랜치: `dev`
- PR: #55
- 작성일: 2026-11-12
- 담당 영역: 게임플레이·제작
- 작업 목적: 고정된 일직선 전투 바닥을 전투 시드로 만드는 절차적 맵으로 바꾸고, 맵이 항상 끊김·구멍 없는 한 덩어리가 되게 한다.

## 주요 요청

1. 선형 맵을 절차적 타일 맵으로 바꾸되, 먼저 구조·에셋을 분석하고 계획만 제시한다.
2. `Assets/temp/FloorTiles01` 에셋만 쓰고 새 에셋은 만들지 않는다.
3. 맵은 하나로 연결되고 구멍·빈 타일이 없어야 하며, 이를 랜덤에 맡기지 않고 알고리즘으로 보장한다.
4. (중간 피드백) 모험가 이동은 나중에 NavMesh로 하므로 구현하지 않고 맵 생성에 집중한다.
5. (중간 피드백) 좁은 길 느낌 없이, T자·L자가 아닌 탐험하기 좋은 덩어리 모양으로, 던전마다 타일 에셋 하나만 쓴다.
6. (중간 피드백) 맵 크기를 키운다.

## AI와 논의한 내용

### 지금 구조 분석

전투 바닥은 `Battle` 씬의 Plane 한 장이었고, 전투 시뮬레이션은 1차원 위치라 유닛이 +X로 곧게 걸었다. FloorTiles01은 이음매 없는 정사각 바닥 텍스처 10종과 Built-in Legacy 셰이더 머티리얼뿐이라, 모서리·가장자리 타일 없이 격자 알고리즘으로 연결성을 보장해야 한다고 정리했다.

### 생성 방식 변천

1. 조각 격자 + 신장 트리(큰길 + 곁가지, T·L·원형 조각)와 유닛 경로 따라가기를 구현했다.
2. 사용자가 "T·L·원형은 조각이 아니라 전체 모양의 기준"이라고 정정해, 맵 전체 틀을 L·T·원형으로 잡고 노이즈로 변형하는 방식으로 바꿨다. 경로 따라가기는 되돌렸다.
3. 사용자가 T·L 모양과 좁은 길을 원하지 않아, 크게 겹치는 타원 덩어리를 이어 붙이고 노이즈로 휘는 방식으로 확정했다.

### 연결성·빈 공간 보장

가장 큰 덩어리만 남기기 → 최소 폭보다 좁은 목·돌기 제거(정사각형 열림 연산) → 다시 가장 큰 덩어리만 남기기 → 안쪽 구멍과 대각선 접촉 메우기 순서로 정리한다. 검증기(한 덩어리, 구멍 0, 대각선 접촉 0, 좁은 칸 0)를 통과하지 못하면 다른 시드로 다시 만들고, 끝내 실패하면 변형하지 않은 틀을 쓴다.

## 주요 결정

- (사용자) 1차 범위는 맵 생성까지. 모험가 이동은 이후 NavMesh 작업에서 한다.
- (사용자) 맵은 넓은 덩어리 모양. 좁은 통로와 T자·L자 모양은 쓰지 않는다.
- (사용자) 던전 하나는 바닥 타일 에셋 하나만 쓴다. 나중에 비슷한 타일 묶음에서 고른다.
- (사용자) 맵 크기를 길이 기준 2배로: 긴 변 180~240m, 가장 좁은 곳 24m 이상 ([추정], `StageMapData`).
- (사용자) FloorTiles01은 `ThirdParty`로 옮기고 URP Lit로 변환해 커밋한다. Standard Unity Asset Store EULA(무료)이고 임시 에셋이라 나중에 교체한다.
- (구현) 맵은 시드만으로 다시 만들 수 있어 네트워크 동기화를 추가하지 않는다. 노이즈는 정수 해시로 계산해 기기마다 같다.
- 기획 7.2 "맵 생성"을 위 결정대로 고쳤다.
