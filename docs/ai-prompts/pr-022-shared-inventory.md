# PR #22: feat: 공용 창고와 플레이어 슬롯 8칸, 드래그 앤 드롭 인벤토리 추가

- 작업 목적: 대장간·파견 창과 이어질 수 있는 독립된 공용 창고와 플레이어 슬롯 8칸 구현

## 주요 요청

1. 독립된 공용 인벤토리를 먼저 만들고, 그다음 플레이어 인벤토리 8칸을 만들 것
2. 공용 인벤토리는 대장간, 전투 파견 창과 잘 이어지도록 구조를 제안할 것
3. 공용 인벤토리는 5×10으로 시작하고, 가득 차면 5×15, 5×20처럼 계속 늘어날 것
4. 두 인벤토리 모두 칸 안에서 드래그 앤 드롭으로 물건을 옮길 것
5. 공용 인벤토리는 특정 물건(상자 등)에 상호작용하면 열리고, 플레이어 8칸은 화면 하단에 항상 떠 있을 것

## AI와 논의한 내용

### 구조

AI는 세 가지를 제안했다.
- 창고 데이터(`SharedInventoryState`)와 여는 상자를 나눈다. 그러면 제작·파견 창·전투 보상이 상자와 관계없이 창고를 직접 참조할 수 있다.
- 칸 규칙은 `Core/Inventory`에 하나만 둔다. 공용 창고와 플레이어 슬롯은 크기 수치만 다르게 쓴다.
- 이동 RPC는 처음부터 "출발 인벤토리·칸 → 도착 인벤토리·칸" 형태로 만든다. 그러면 창고 ↔ 내 슬롯 이동을 새 RPC 없이 처리할 수 있다.

### 늘어나는 크기의 상한

Fusion의 `[Networked]` 배열은 최대 크기를 컴파일할 때 정해야 한다. 그래서 "계속 늘어남"에도 상한이 필요하다는 점을 AI가 짚었다.

### 사용자에게 확인한 항목

- 격자 방향
- 최대 크기
- 쌓기 여부
- 창을 연 동안의 이동

### 확인 중 발견한 문제

창을 연 채로 씬을 내리면, 상자가 이미 파괴된 창을 닫으려다 오류가 났다. 파괴 여부를 확인하도록 고쳤다.

## 주요 결정

- 사용자 결정
  - 가로 5칸 × 세로 10줄로 시작해 아래로 5줄씩 늘어난다.
  - 최대 크기는 5×40(200칸)이다.
  - 재료만 쌓는다. 같은 재료이면서 등급도 같아야 한다.
  - 창고 창을 연 동안 캐릭터 이동을 잠근다.
  - 공용 창고를 먼저 만들고, 그다음 플레이어 8칸을 만든다.
- 구현 과정에서 정한 것
  - 칸 규칙은 `Core/Inventory`의 `InventoryGrid`에 두고, 호스트 소유 상태는 `NetworkInventory`를 이어받아 만든다.
  - 호스트는 출발 칸의 물건이 요청 당시와 같은지만 확인한다. 동시 이동 충돌을 막기 위한 것이다.
  - 공용 창고는 여러 명이 동시에 열 수 있고, 점유는 두지 않는다.
  - [추정] 재료 한 칸 최대 개수는 99로 하고 데이터에 둔다.
  - 시험용 아이템 5종을 임시로 둔다. 아이템 정의는 `03.ScriptableObjects/Items`에 두고 `CLAUDE.md` 폴더 구조에 추가한다.
  - 재접속한 플레이어에게 슬롯을 이어 주는 일은 플레이어 식별 방식이 정해진 뒤 한다.

## 검증 내용

- EditMode 테스트 159개가 모두 통과했다(인벤토리 18개 추가).
- AI가 `InventoryTest` 씬 플레이 모드에서 확인했다. 키 입력은 Input System 이벤트로, 끌어다 놓기는 칸 화면의 드래그 처리 함수를 직접 불러 넣었다.
  - 창고가 늘어나는 것, 재료가 쌓이는 것
  - 창을 열고 닫을 때 잠금이 걸리고 풀리는 것
  - 창고 안, 내 슬롯 안, 창고 ↔ 내 슬롯의 옮기기·맞바꾸기·합치기
  - 창을 연 채 종료해도 오류가 나지 않는 것
- 사용자가 실제 마우스로 끌어다 놓기를 확인했다.
- 두 명 접속은 아직 확인하지 않았다.
