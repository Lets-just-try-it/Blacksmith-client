## AI와 논의한 내용

### 파티 동기화 방식

AI는 처음에 파견 시점의 모험가 정보를 통째로 담는 스냅샷을 추천했다. 관리 목록 ID만 보내면 결과 반영이나 장비 변경이 재생 중인 참가자에게 영향을 줄 수 있다는 이유였다. 사용자가 실제 흐름(낮 영업 종료 → 호스트가 스테이지와 파티 선택 → 파견 → 전투 → 결과창 → 다시 낮)을 설명했고, 그 흐름에서는 위험 대부분이 사라진다는 데 합의해 ID만 보내기로 했다.

### 결과 반영 시점

사용자가 결과를 담아 두었다가 전투가 끝난 직후나 씬 전환 직전에 반영하는 방안을 제안했다. AI는 재생이 끝나는 시점이 참가자마다 달라 "끝난 직후"에 반영하면 아직 재생 중인 참가자의 레벨업 표시가 틀어질 수 있다고 보고, 씬 전환 직전(전투 씬을 내리기 직전)을 제안했다. 사용자가 이를 따랐다.

### 지속 상태와 씬을 여는 방식

AI가 씬을 통째로 바꾸면 관리 목록과 진행 상황이 사라져 씬 밖에 둘 구조가 필요하다고 설명했다. 사용자가 씬 전환이 무겁지 않은지 물었고, AI는 로딩보다 매일 낮 씬을 다시 만드는 구조 부담이 크다고 보고 Additive, 같은 씬, 씬 전환을 비교해 Additive를 추천했다. 사용자가 Additive 씬이 카메라·UI·조명을 공유하는지 물었고, AI는 공유되지 않지만 함께 렌더링되어 겹치므로 낮 씬 쪽을 꺼야 한다고 설명했다. 사용자는 Additive로 정하고, 이번 PR은 문서만 반영하기로 했다.

### 두 명 접속 확인

AI가 호스트 혼자서는 클라이언트 경로를 확인할 수 없다고 알렸다. 사용자가 실제 흐름에는 전투 씬으로 넘어갈 트리거가 없다는 점을 짚었고, AI가 로비의 Game 씬 경로를 에디터에서만 임시로 바꾸는 방법을 안내하고 설정했다. 사용자가 빌드와 두 명 접속으로 확인했다. 사용자가 늦게 들어온 참가자가 전투를 처음부터 재생하는 것을 발견했고, 재접속 처리와 함께 후속 작업으로 미루기로 했다.
