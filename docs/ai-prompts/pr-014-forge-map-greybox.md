## 주요 요청

1. 쿼터뷰와 1인칭 중 어느 시점이 맞을지 추천받고, 추가했던 외부 에셋(Quaternius)은 모두 제거한 뒤 그레이박스로 테스트한다.
2. 쿼터뷰에서 게임이 돌아가는 모습을 보고 싶으므로 여러 쿼터뷰 카메라 시점을 골라 볼 수 있게 한다.
3. 바닥이 어색하므로 씬의 바닥을 작업장 크기에 맞추고 나머지 바닥은 없앤다.
4. 씬 카메라 기본 위치를 대장간이 잘 보이게 하고 대장간을 씬 중앙으로 옮긴다.
5. 플레이어가 대장간 밖으로 떨어지지 않게 막는다.

## AI와 논의한 내용

### 쿼터뷰와 1인칭

경영·육성 게임 특성상 작업대와 구역 전체를 봐야 하므로 쿼터뷰를 기본으로 하고, 1인칭은 비교용 시험 기능(V 키)으로만 남기는 것으로 논의했다.

### 카메라 시점 프리셋

이동이 카메라 방향 기준이라 방위(yaw)는 게임과 같은 45도로 고정하고 높이·거리·투영만 바꾸는 프리셋 6종(Default, Wide, High, Low, Close, Ortho)을 두기로 했다. 6번 Ortho가 정투영 쿼터뷰에 가깝고, 기본(1번)은 기존 Game 씬 카메라와 같은 각도다.

### 바닥 겹침과 작업장 바닥

대장간 바닥과 Game 씬의 바닥이 같은 높이에서 겹쳐 깜빡이는 현상이 있었다. 높이를 띄우는 방법을 시도했다가 되돌리고, ForgeTest 씬에서 바깥 바닥을 제거해 해결했다. 스폰 지점은 대장간 안으로 옮겼고 입구는 보이지 않는 막으로 막았다.

### 외부 에셋과 모델링 도구

Quaternius 에셋은 제거했다. 이후 아트 방향은 팀 안에서 더 논의하기로 했고 이번 PR에는 반영하지 않았다.

## 주요 결정

- 사용자가 확정한 결정
  - 외부 에셋을 모두 제거하고 그레이박스로 테스트한다.
  - 기본 시점은 쿼터뷰로 한다.
  - 작업장 바닥만 남기고 대장간을 씬 중앙에 둔다.
  - 이전 커밋에 바닥·입구 수정까지 합쳐 하나의 커밋으로 올린다.
- 구현 과정에서 확정된 결정
  - 대장간은 20m x 16m, 판매·관리·제작 3구역, 문 3개, 작업대 7개로 배치한다.
  - 시험용 카메라(`ForgeTestCameraFollow`)는 Game 씬에 카메라 추적이 생기면 삭제한다.
- 기획 변경: `docs/GAME_CONCEPT.md` 4.1에 대장간 배치를 반영했다. 다른 영역 담당자와 팀 공유가 필요하다.
