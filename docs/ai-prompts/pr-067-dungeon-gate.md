## 개요

- 대상 브랜치: `dev`
- PR: #67
- 작성일: 2026-11-12
- 담당 영역: 게임플레이·제작
- 작업 목적: 광장에서 전날 밤 모험가가 클리어한 던전(채집 맵)으로 들어가는 문을 만들고, 채집 맵을 메모리를 아끼는 방식으로 만들고 버리며, 멀티 채집 규칙을 기획에 정리한다(기획 2.3, 7.4).

## 주요 요청

1. 광장에 채집할 던전으로 이동하는 문 형식의 오브젝트를 만든다. 갈 수 있는 던전은 전날 모험가가 클리어한 하나뿐이라 선택하지 않는다.
2. 들어갈 던전이 없으면 "던전에 몬스터가 잔뜩 있습니다. 위험합니다." 같은 UI를 띄우고 이동을 막는다.
3. 채집 맵은 들어갈 때 만들고 다음 날 버린다. 멀티 상황을 고려하고, 생성 시간은 문으로 들어갈 때 화면이 어두워지는 동안 숨긴다.
4. 멀티 채집 규칙과 채집 중 낮이 끝날 때의 처리를 정한다.

## AI와 논의한 내용

### 문의 목적지

채집 맵을 그리는 곳이 아직 없었다. 문만 만들기, 최소 채집 구역, 시체까지 포함하는 세 가지를 제시했고, 사용자가 최소 채집 구역(같은 시드로 바닥만 깔고 돌아오는 포털)을 골랐다.

### 맵을 시드로 다시 만들지, 만든 맵을 보관할지

사용자가 메모리 관점에서 두 방식을 비교해 달라고 했다. 런타임에는 프리팹을 저장할 수 없고, 늦게 들어온 참가자와 저장·불러오기 때문에 시드로 다시 만드는 경로는 어차피 필요하다. 그래서 시드로 다시 만들고 생성 코드를 하나로 두는 쪽을 권했다. 사용자는 들어갈 때 만들고 다음 날 버리는 방식으로 바꾸라고 했다.

### 멀티에서 맵을 만들고 버리는 시점

호스트는 다른 플레이어의 캐릭터도 물리로 움직이므로 호스트에도 바닥이 있어야 한다. 그래서 들어가는 본인은 화면이 어두워진 뒤에, 호스트는 다른 플레이어가 문에 닿을 때 만든다. 지난 맵은 참가자마다 맵 영역 안에 플레이어가 없을 때 버린다. 화면이 어두워진 뒤 맵을 만들려면 `PlayerAreaTravel.Travel`(Network 공개 API)에 콜백이 필요했고, 사용자가 선택 인자 추가를 승인했다.

### 멀티 채집 규칙

사용자가 같은 채집 맵에 함께 들어가는 것이 맞는지 물었다. 협동 기획(9절)과 호스트 소유 상태 구조에 맞으므로 공유를 권했고, 사용자가 공유로 정했다. 자원 처리와 낮이 끝날 때의 처리는 사용자가 정했다.

## 주요 결정

- 광장의 던전 문으로 들어가고 맵 시작 지점 옆 포털로 돌아온다. 채집할 곳이 없으면 안내를 띄우고 막는다(사용자 결정, 기획 7.4 `[미정]` 정리).
- 채집 맵은 참가자마다 들어갈 때 만들고, 채집할 맵이 바뀌면 안에 플레이어가 없을 때 버린다(사용자 결정).
- `PlayerAreaTravel.Travel`에 선택 인자 `onScreenDark`를 추가했다(사용자 승인, Network 공개 API).
- 멀티에서는 모든 플레이어가 같은 채집 맵을 쓴다(사용자 결정, 기획 7.4).
- 자원은 호스트가 관리하는 공용 상태로, 한 명이 캐면 모두에게 사라지고, 같은 자원은 작업대처럼 먼저 시도한 플레이어가 캐며, 재료는 캔 플레이어의 개인 인벤토리로 들어간다(사용자 결정, 기획 7.4).
- 낮이 끝날 때 진행 중인 채집은 미니게임처럼 끝까지 진행한 뒤 밤이 되고, 다음 날은 대장간에서 시작한다(사용자 결정, 기획 2.3·7.4). 이에 맞춰 파견을 건너뛸 때도 모든 플레이어를 대장간으로 옮긴다.
- 채집 맵은 전투 공간과 겹치지 않게 x = 2000에 두고, 안내 문구는 기존 `ForgeNotice`를 재사용했다.
