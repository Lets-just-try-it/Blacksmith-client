# PR #7: feat: 장비 등급 5단계 규칙과 경계값 데이터 추가

## 개요

- 브랜치: `feat/equipment-grade-rule`
- 대상 브랜치: `dev`
- PR: #7
- 작성일: 2026-11-01
- 담당 영역: 게임플레이·제작 (`Forge/`, `Core/`)
- 작업 목적: 미니게임 점수를 장비 등급으로 바꾸는 규칙을 확정하고, 이후 제작 미니게임 이식이 기댈 등급 계산과 데이터를 먼저 만든다.

## 주요 요청

1. 별도 프로젝트(`Blacksmith_TEST`)에서 만든 제작 미니게임 프로토타입 7종을 현재 프로젝트에 맞게 이식할 것. 프로토타입은 기능만 가져오고 현재 프로젝트 기준을 우선한다.
2. 장비 완성도를 5단계로 나눌 것. 이름은 최하급~최상급, 모든 장비는 각 미니게임 점수의 평균으로 등급을 정한다.
3. 등급 구간은 AI가 제안한 예시(0.40/0.60/0.75/0.90)를 쓸 것.
4. 장신구도 단계별 점수의 단순 평균으로 계산할 것.
5. 이식은 PR을 나눠 진행하고, 이번 PR에는 등급 규칙과 데이터만 포함할 것.

## AI와 논의한 내용

### 프로토타입 분석과 이식 순서

AI가 프로토타입의 규칙·화면·실행기 구조와 현재 프로젝트 규칙의 충돌 지점을 정리했다.
- 규칙 클래스는 이미 `System.Random(seed)`를 쓰고 Unity에 의존하지 않아 이식이 쉽다.
- 밸런스 수치가 클래스 안의 상수로 흩어져 있어 ScriptableObject로 옮겨야 한다.
- 화면은 즉석 그리기 방식(IMGUI)이라 현재 프로젝트의 UI 방식으로 다시 만들어야 한다.
- 입력은 구 입력 API를 써서 Input System으로 바꿔야 한다.

사용자는 7종을 모두 옮기고, 현재 프로젝트 기준을 최우선으로 하며 프로토타입은 기능만 옮기기로 했다. AI는 규칙 → 입력 → 화면 → 네트워크 연결 순서로 PR을 나누자고 제안했다.

### `Accuracy` 형식

AI가 `Accuracy`의 형식을 `0~1` 실수와 `0~100` 정수로 비교했다. 프로토타입이 이미 `0~1` 점수를 쓰고, 등급 계산은 호스트에서 한 번만 하므로 실수 오차가 문제되지 않는다. `0~1` 실수로 정했다.

### 등급 구간

AI가 프로토타입의 3등급 경계(0.76, 0.42)를 참고해 5단계 가안(0.40/0.60/0.75/0.90)을 제안했다. 사람 기준으로는 플레이 테스트 후 다시 맞춰야 하므로, 경계값을 ScriptableObject 데이터에 두기로 했다. 사용자가 가안을 그대로 쓰기로 했다.

### 테스트 구조와 팀 영향

AI가 `Core`를 별도 어셈블리로 만드는 것(`Core.asmdef`)을 처음 제안했다. 사용자가 필요성과 팀 영향을 물었고, AI는 등급 규칙 자체에는 필요하지 않으며 모든 영역이 영향을 받는 구조 변경이라고 답했다. 사용자는 이번 PR에서 제외하기로 했다. 이후 `origin/dev`에 팀원이 같은 목적의 `Blacksmith.Core.asmdef`와 EditMode 테스트 구조를 이미 넣은 것을 확인했고, 그 구조 위에서 테스트를 추가했다.

### 병합 충돌 처리

작업 중 `dev`에 PR #4~#6이 병합되어 두 번 병합했다.
- 폴더 `.meta` 충돌은 팀원 쪽 GUID를 채택했다.
- `PROJECT_PROGRESS.md`는 팀원이 바꾼 구조(기준 커밋 표기 삭제)를 따랐다.
- 로컬에 남은 `ProjectSettings` 변경은 줄바꿈 차이뿐이었고, 사용자가 폐기를 승인했다.

## 주요 결정

- 장비 등급을 5단계(최하급·하급·중급·상급·최상급)로 확정, 각 미니게임 점수의 평균으로 계산 (사용자 결정)
- 구간 경계 0.40/0.60/0.75/0.90, 하한 포함. 경계는 [추정]으로 두고 플레이 테스트 후 조정 (사용자 결정)
- `Accuracy`는 0~1 실수 (사용자 결정, `docs/GAME_CONCEPT.md` 12번 항목과 `docs/NETWORK_DESIGN.md`의 [미정] 정리)
- 장신구는 네 단계 점수의 단순 평균, 이식 단계에서 `NecklaceGame`이 단계별 점수를 내놓도록 고치는 것을 허용 (사용자 결정)
- 계산은 `Core/GradeRule`, 경계값과 등급 이름은 `Forge/GradeThresholdData`와 `GradeThresholds.asset`에 분리 (AI 제안, 사용자 승인)
- `Core.asmdef` 추가는 이번 PR에서 제외 (사용자 결정)

## AI 활용 범위

AI가 프로토타입 분석, 설계 제안, 코드·테스트·문서 작성, 병합 충돌 해결, Unity CLI를 통한 데이터 에셋 생성과 테스트 실행을 맡았다. 사용자는 이식 범위, 등급 개수와 이름, 구간 경계, `Accuracy` 형식, 장신구 평균 방식, asmdef 제외, 로컬 변경 폐기를 직접 결정했다. 커밋과 PR 내용은 AI가 초안을 보이고 사용자가 승인했다. 사용자는 GitHub 로그인(기기 인증)을 직접 했다. 기획 변경의 팀 공유는 사용자가 직접 한다.
