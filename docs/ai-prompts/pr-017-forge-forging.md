- 대상 브랜치: `dev`
- PR: #17

- 작업 목적: 프로토타입의 단조(리듬 망치질)를 규칙과 작업대 화면, 소리·타격 연출까지 옮겨 대장간 맵에서 해볼 수 있게 한다.

## 주요 요청

1. 단조 기능을 추가한다. 방식, 타수·제한시간은 프로토타입 기준으로 하고, 이번 PR은 규칙과 작업대 화면까지로 한다.
2. 사운드와 입력했을 때의 타격감을 살린다.
3. 단조 상호작용 범위를 뒤쪽 큰 빨간 작업대 주변으로 잡는다.
4. 판정이 정확했다고 느낀 순간에도 "느림"으로 나오는 것을 고친다.
5. 박자 레인은 화면 아래 원래 위치로 유지한다.
6. 소리는 불필요한 것을 정리하되 차징, 헛스윙, 결과 소리는 남기고, 화면 번쩍임은 줄인다.

## AI와 논의한 내용

### 프로토타입 확인

단조 세부 방식은 기획 문서에 없는 항목이라, 사용자에게 방식과 범위를 물었다. 사용자가 "프로토타입과 같은 기능"으로 하라고 해서 저장소 밖 `Scripts.zip`의 `ForgeGame`, `ForgeView`를 읽고 옮겼다. 수치는 코드 상수가 아니라 데이터로 빼고, 난이도 0은 프로토타입 값, 1·2는 임시 값으로 두었다.

### 판정이 느리게 나오는 문제

키 입력, 박자 소리, 화면이 도착하는 지연 때문에 소리와 화면을 보고 누르면 게임 시계보다 늦게 입력된다고 보았다. 판정 보정값(`InputOffset`, 기본 0.06초)을 데이터에 두고, 판정 문구에 박자와의 차이(ms)와 한 판의 평균 타이밍을 보여 줘 값을 맞출 수 있게 했다. 사용자가 보정 후 판정이 괜찮다고 확인했다.

### 화면 구성

박자 레인을 작업대 앞 월드로 옮겨 봤으나 사용자가 원래 위치(화면 아래)가 낫다고 해서 되돌렸다. 카메라는 캐릭터가 작업대를 가려, 단조 중 내 캐릭터를 내 화면에서만 숨기는 방식으로 해결했다.

### 소리와 타격감

프로토타입의 절차 생성 효과음과 연출(불꽃, 충격파, 조명, 화면 흔들림·확대·번쩍임, 규칙 시간 잠깐 멈춤)을 옮겼다. 사용자가 소리를 확인한 뒤 박자 톡 소리와 놓침 소리는 빼고 차징, 헛스윙, 결과 소리는 남기기로 정했고, 화면 번쩍임은 약하게 줄였다. 맞는 순간 규칙 시간을 멈추는 동안 누른 입력은 모아 뒀다가 이어서 처리한다.

## 주요 결정

- 사용자가 확정한 결정
  - 단조는 프로토타입의 리듬 방식으로 하고, 수치도 프로토타입 기준으로 한다. (기획 변경)
  - 이번 PR은 규칙과 작업대 화면까지로 한다.
  - 상호작용 범위는 큰 빨간 작업대 주변으로 한다.
  - 박자 레인은 화면 아래에 둔다.
  - 소리는 망치 내려치는 소리, 차징, 헛스윙, 결과 소리를 낸다.
  - 화면 번쩍임은 약하게 한다.
  - 직접 확인하지 못한 항목이 있으면 PR 전에 사용자에게 확인을 요청한다.
- 구현 과정에서 확정된 결정
  - 판정 보정값(기본 0.06초)을 데이터에 두고 판정 문구에 ms를 보여 준다.
  - 단조 중 내 캐릭터는 내 화면에서만 숨긴다.
  - 효과음 파일이 없어 코드로 만든 임시 효과음을 쓴다.
- 기획 변경: `docs/GAME_CONCEPT.md`에 단조 항목을 추가했다. 이전 기획의 "위치 선택" 방식 대신 리듬 방식을 쓰고, 한 판의 길이는 박자표가 정한다. 팀 공유가 필요하다.
