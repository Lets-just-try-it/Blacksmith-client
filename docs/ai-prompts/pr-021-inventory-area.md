## 개요

- 브랜치: `docs/inventory-area`
- 대상 브랜치: `dev`
- PR: #21
- 작성일: 2026-11-03
- 담당 영역: 공통 문서
- 작업 목적: 인벤토리를 대장간에서 분리해 별도 영역으로 두고, 진행 현황의 테스트 수와 남은 작업 정리

## 주요 요청

1. 진행 현황 문서의 테스트 수를 갱신할 것
2. 자동 전투에 남은 작업 목록을 정리할 것
3. 인벤토리를 대장간, 자동 전투와 별개로 맡기로 했으니 인벤토리 작업 목록을 정리할 것

## AI와 논의한 내용

### 테스트 수 확인

AI가 테스트 파일의 `[Test]`·`[TestCase]` 수를 세고, 실행 중인 에디터에서 EditMode 테스트를 돌렸다. 141개 모두 통과했고, 진행 현황 문서의 항목별 개수 합도 141개로 맞았다.

### 자동 전투 남은 작업

AI가 진행 현황과 기획 문서를 바탕으로 남은 작업을 세 묶음으로 정리했다.
- 전투 영역에서 바로 할 수 있는 일: 전투 씬을 Additive로 불러오도록 정리, 임시 연결 정리, 보스 클리어 컷씬과 단계 해금, 몬스터 아트와 수치, 늦게 들어온 참가자 동기화, 전투 HUD 한글 폰트
- 다른 영역에 기대는 일: 결과 반영, 파견 창 연결, 장비 반영, 직업별 공격 방식
- 정해야 할 항목: 클리어한 단계 재도전, 전체 던전 단계 수, 최대 레벨, 재료 종류, 장비·직업 보정

### 인벤토리 담당 표기

문서에서 인벤토리를 "전투" 담당이라고 적으면, 인벤토리가 전투 기능의 일부로 읽힐 수 있다는 우려가 나왔다. AI는 두 가지를 비교했다.
1. 인벤토리를 별도 영역으로 두기
2. 전투 영역에 넣어 적기

문서에서 "대장간·광장·전투"는 사람이 아닌 기능 영역 이름으로 쓰인다. 또 인벤토리는 제작, 판매, 파견 창, 전투 보상이 함께 쓰는 시스템이다. 그래서 AI는 1번을 추천했다.

## 주요 결정

- 사용자 결정
  - 인벤토리를 네 번째 영역으로 둔다.
  - 문서에 전투 담당이 맡는다고 적지 않는다.
- 구현 과정에서 정한 것
  - 코드는 `Assets/02.Scripts/Inventory/` 도메인 폴더에 둔다.
  - 인벤토리에서 정해야 할 항목은 진행 현황의 남은 작업에 적는다: 공용 창고 칸 수, 같은 아이템 쌓기, 슬롯이 가득 찼을 때 처리, 파견 뒤 장비 반환.
