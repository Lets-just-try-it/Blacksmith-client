## 주요 요청

1. #4가 병합된 뒤에도 `docs/PROJECT_PROGRESS.md`의 기준 브랜치 커밋이 #3 병합 커밋으로 남는 문제를, 팀원이 직접 고치지 않아도 되도록 해결할 것
2. 남은 작업 목록과 시스템 표 정리는 미뤘다가 이번 작업에 함께 넣을 것

## AI와 논의한 내용

### 기준 커밋이 어긋나는 원인

AI는 원인을 이렇게 설명했다. PR은 자신이 병합될 때 생기는 커밋 해시를 미리 알 수 없으므로, PR 안에서 적은 기준 커밋은 항상 병합 직전 값으로 남는다.

### 해결 방법

세 가지 방법을 비교했다.
1. 문서에서 해시를 빼고, 문서가 들어 있는 브랜치의 상태를 설명한다고 명시한다.
2. 이름만 "작성 기준 커밋"으로 바꿔 지금 방식을 유지한다.
3. GitHub Actions로 병합 뒤 자동 갱신한다.

2번은 읽는 사람이 헷갈리는 문제가 그대로 남는다. 3번은 보호 브랜치에 봇 커밋 예외가 필요해 무겁다. AI는 1번을 추천했다.

## 주요 결정

- 사용자 결정
  - 진행 현황 문서에서 기준 커밋 해시를 뺀다. (1번)
  - 미뤄 둔 진행 현황 정리(남은 작업 갱신, "숙련도·장인 슬롯" 행 삭제)를 같은 커밋에 넣는다.
- 구현 과정에서 정한 것
  - 같은 문제가 다시 생기지 않도록 `CLAUDE.md` 규칙에 해시를 적지 않는다는 내용과 이유를 적는다.
